# Atividade 1 - Software é intangível

A engenharia de software também se diferencia de outras áreas da engenharia, pois áreas como engenharia civil, engenharia mecânica e engenharia aeronáutica utilizam do conhecimento teórico para criarem coisas físicas, e para isso devem seguir diretrizes extremamente rigorosas, já que um erro pode custar a vida de outras pessoas, enquanto a engenharia de software utiliza do conhecimento teórico para criar algo não-material, fazendo com que não tenham diretrizes tão rigorosas como as outras áreas.

# Atividade 2 - Engenharia de Software = Programação + Tempo, Escalabilidade e Trade Offs

Segundo os engenheiros e engenheiras do google, programação seria o ato de escrever códigos e desenvolve-los, já a engenharia de software necessita aplicação teórica para produzir algo real e preciso. A engenharia de software pode ser definida como "programação integrada ao longo do tempo", que basicamente quer dizer que um engenheiro de software além de programar, deve pensar no tempo de vida do código e como ele se adaptará com o passar do tempo, pensar em como o código se adaptará ao crescimento da empresa, e em como a empresa deverá fazer decisões com base nos fatores de tempo e crescimento citados anteriormente.

# Atividade 3 - 5 Requisitos não funcionais

#### Escalabilidade:
- Capacidade de escalar um software para se manter funcional mesmo com grandes quantidades de usuários ao mesmo tempo, como o Google, que tem bilhões de usuários o tempo todo e precisa se manter em perfeito estado para esses bilhões de usuários.
#### Segurança
- Processos e funcionalidades para proteger dados e informações tanto do usuário quanto do software, para que não aja brechas para ataques hackers ou vazamento de dados.
#### Performance
- Capacidade de executar o software da maneira mais eficiente possível, fazendo mais e utilizando menos, essencial para que o software rode em dispositivos mais fracos executando tarefas com a mesma eficiência comparado a um dispositivo mais potente.
#### Agilidade
- Característica estrutural que facilita e possibilita práticas de desenvolvimento de software, para melhor manutenção e atualização do software.
#### Usabilidade
- Característica que faz o software ser simples, rápido e eficiente para qualquer tipo de pessoa.

# Atividade 4 - Trade Offs

#### Consistência (SQL) X Disponibilidade (NoSQL):
- SQL Garante que todos os usuários vejam o mesmo dado ao mesmo tempo (ideal para transferências bancárias). Se houver falha de rede, o sistema pode bloquear o acesso, sacrificando a disponibilidade.
- NoSQL Garante que o sistema responda sempre, mesmo que o dado esteja desatualizado por alguns milissegundos, como em curtidas ou no Instagram, priorizando que o app nunca caia.

#### Usabilidade (Whatsapp) X Segurança (Aplicativos de banco):
- No whatsapp o usuário já entra rapidamente na aplicação sem nenhum tipo de verificação,  facilitando muito o uso do software e poupando tempo, mas isso também torna as conversas das pessoas vulneráveis, pois se outra pessoa pegar ou roubar o celular, terá acesso livre as conversas, e por mais que exista a função de senha, ela não é ativada por padrão justamente pelo bem da usabilidade.
- Já aplicativos bancários sempre pedem senha e verificações toda vez que o usuário entra no aplicativo, tornando bem seguro, mas tornando a experiência do usuário bem cansativa.

#### Desempenho (Unreal engine/C++) X Manutenibilidade (Unity/C#):
- Ambos engines para desenvolvimento de jogos, Unreal utiliza C++ para trazer melhor desempenho técnico aos jogos produzidos, mas peca na facilidade de manutenção do software.
- Já Unity usa C#, que traz uma facilidade maior na manutenção do software e desenvolvimento dos jogos, ao custo de ter menos desempenho e performance.
